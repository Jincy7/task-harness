# 작업 흐름에서 질문 만들기

최종 연습에서 읽습니다. 문항은 대상 저장소의 실제 작업을 설명하게 만드는 질문이며, 특정 프로젝트의 문제를 다시 출제하는 목록이 아닙니다.

## 근거에서 후보 선택

1. 현재 요구, 사용자 결정, AI에 맡긴 분석, 변경 코드와 검증 기록을 읽습니다. 기록의 버전을 확인하고 현재 작업에 관련된 부분만 사용합니다.
2. 사용자 행동부터 결과까지 흐름을 따라가며 결과를 바꾼 판단, 실패나 수정, 확인된 보장과 남은 가정을 찾습니다.
3. 각 질문 후보에 내부 메모로 `판단 대상 / 근거 위치와 버전 / 확인된 사실 / 미확인 / 설명을 확인할 이유`를 연결합니다.
4. 결과에 미치는 영향, 잘못 설명할 위험과 다른 후보와의 중복을 보고 중요한 후보를 고릅니다. 같은 판단을 표현만 바꿔 여러 문항으로 세지 않습니다.
5. 기본 6문항을 구성하되 사용자 지정 수를 우선합니다. 의미 있는 후보가 부족하면 부족한 근거를 알리고 확인 가능한 수만 진행합니다. 없는 작업을 만들어 수를 채우지 않습니다.

다음 영역은 후보를 찾는 관점입니다. 영역별 한 문항을 강제하지 않으며, 해당하지 않는 영역은 실제 작업의 다른 중요한 판단으로 대체합니다.

| 관점 | 작업 기록에서 찾을 것 |
| --- | --- |
| 모호한 요구의 결정 | 주어진 요구, 관찰, 비교한 정책, 선택 이유와 영향 |
| 데이터 흐름과 보호 | 입력, 변환, 저장, 출력, 소유자와 접근 경계 |
| 유효성과 가정 | 구현한 검사, 실행 근거, 미구현 조건, 보정과 제외 |
| AI에 위임한 분석 | 실제 지시, 비교 결과, 독립 검증과 알고리즘의 한계 |
| 변경과 겹치는 작업 | 입력 변경, 오래된 결과, 중복 요청, 확정과 복구 정책 |
| 제안의 채택과 기각 | 실제 제안, 결정 주체, 수정 이유와 결과 |

예를 들어 로그인 없는 단일 사용자 변환 도구에 역할별 로그인 문항을 넣지 않습니다.
관련성이 있으면 출력 파일 덮어쓰기, 잘못된 행의 처리, 재실행 결과나 파일 접근 범위를 대신 확인합니다.
분석을 맡긴 기록이 없으면 “AI에 어떤 알고리즘 분석을 시켰는가”라고 전제하지 않습니다.
기록이 부족한 선택은 당시 이유가 확인되지 않았음을 밝히고, 현재 구현의 동작이나 보장 범위를 질문할 수 있습니다.

## 질문 문장과 답변 대조

저장소의 실제 사용자 행동, 입력이나 상태를 넣어 한 가지 판단을 중심으로 묻습니다.
선택 이유, 대안의 영향이나 실제 보장 범위를 설명할 수 있게 하되 여러 독립 질문을 한 문장에 나열하지 않습니다.
내부 근거 메모의 파일 위치나 정답은 코드 없는 질문 본문에 노출하지 않습니다.
도메인 이름만 바꾼 고정 문항, 함수명 기억 문제, 호출되지 않는 코드의 키워드로 고른 주제를 사용하지 않습니다.

답변은 현재 요구, 실제 코드와 관측에 대조합니다. 실행하지 않은 코드 검토를 실행 증거로 취급하지 않습니다.
코드와 요구가 다르면 구현 결함 가능성을 남기고 코드 그대로 답해야 맞는 것으로 처리하지 않습니다.
사용자의 결정, AI의 제안, 구현한 것과 검증한 것을 구분하는지 확인합니다. 임의의 정답이나 점수를 만들지 않습니다.
문답은 한 번에 하나씩 제시하고 사용자 응답을 기다립니다. 문항 목록 생성만 요청받았다면 목록을 제공하되 사용자 이해 확인 완료로 기록하지 않습니다.

## 복기 자료와의 관계

과거 질문은 어떤 판단이 중요했는지 찾는 참고 사례입니다. 문장, 순서와 여섯 영역이 그대로 반복된다고 가정하지 않습니다.
다른 저장소에서는 그 저장소의 작업 근거로 후보와 질문을 다시 만듭니다.
동일 환경의 복기를 읽었더라도 그 사례의 역할, 데이터 규모나 기술 스택을 현재 프로젝트 요구로 옮기지 않습니다.
