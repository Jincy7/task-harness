# 대화 분기와 예제

먼저 서비스 전체를 관통하는 질문 하나를 제시하고 실제 사용자 응답을 기다립니다.
통합 흐름 연습에서는 답변에서 근거가 약한 지점 하나에만 후속 질문을 사용합니다.

| 응답 | 다음 행동 |
| --- | --- |
| 의미와 이유 및 근거가 충분 | 확인된 범위를 짧게 정리하고 종료 |
| 결과만 정확 | 빠진 판단 근거 하나를 후속 질문으로 확인 |
| 일부 혼동 | 맞는 부분 유지, 혼동된 지점 하나에 설명 또는 질문 |
| 모르겠음 또는 설명 요청 | 짧은 설명과 예제, 도움을 준 범위 기록 |
| 애매한 표현 | 같은 지점의 의미 확인, 오답 단정 금지 |
| 실제 동작의 모순 지적 | 규칙과 코드 및 관측 대조, 제품 문제와 설명 부족 구분 |
| 생략 또는 종료 | 상태와 재개 위치 보존, 요청에 따라 종료 |

예제는 확정 규칙에서 도출합니다. 실행하지 않은 예제는 개념 설명용이라고 밝힙니다.
같은 지점이 해결되지 않아도 변형 사례를 연달아 내지 않고 남은 확인으로 둡니다. 추가 연습은 사용자 요청에 따릅니다.

## 합성 대화 예시

상황: 운영자가 결과를 확정하고 구성원이 조회하는 흐름을 직접 확인했습니다.
현재 화면의 대기 중 버튼 잠금은 확인했고, 서버 재전송 중복 처리는 아직 확인하지 않았습니다.
아래 대화는 실제 사용자 답이나 검증 결과가 아닙니다. 실제 사용에서는 각 질문에서 멈춥니다.

에이전트: 코드를 보지 않고 먼저 90초 동안 설명해 봅니다. 운영자가 데이터를 바꾼 뒤 구성원이 결과를 볼 때까지, 누가 어떤 버전을 읽고 무엇을 확정하나요?

사용자: 운영자가 새 버전으로 계산하고 확정하면 구성원이 그 결과를 봅니다. 버튼이 잠겨서 응답이 끊겨도 확정은 한 번만 저장됩니다.

에이전트: 계산과 조회의 연결은 설명했습니다. 근거를 더 확인할 지점은 재전송 처리입니다. 저장은 끝났지만 응답이 끊겨 다시 전송하면 현재 서버는 확정을 어떻게 처리하나요?

사용자: 화면의 버튼 잠금만으로는 서버 재전송을 막지 못하겠네요. 서버 쪽 보장은 확인하지 않았습니다.

에이전트: 화면의 중복 클릭 방지와 서버 재전송 보장을 구분했습니다. 서버 재전송 처리는 미확인으로 남깁니다.

코드의 파일명이나 호출되지 않는 함수는 시작 질문의 주제를 정하는 기준이 아닙니다.
사용자가 추가 설명을 요청하면 근거를 보여주되, 바로 따라 말한 답을 독립 설명으로 기록하지 않습니다.

## 최종 연습과 기록

최종 연습은 `SKILL.md`의 6개 판단 영역을 따릅니다. 문제는 실제 결정과 산출물에 맞게 작성하고, 문항마다 응답을 기다립니다.
연습 중 정답과 힌트를 먼저 주지 않으며, 요청으로 제공했다면 도움을 받은 문항으로 기록합니다.
사람 검증이 남은 최신 화면은 미확인으로 기록하며 과거 화면 확인으로 대체하지 않습니다.

기존 보고에 필요한 행만 남깁니다. 다음 표는 빈 형식이며 사용자 응답 없이 결과를 채우지 않습니다.

| 대상 / 모드 | 사례와 답변 요지 | 도움을 준 범위 | 상태 / 남은 확인 |
| --- | --- | --- | --- |
| | | | |

코드 상태, 실행 주소와 사람 검증 근거는 기존 보고의 정보를 참조합니다.
설명 확인과 제품의 자동 및 사람 검증 결과를 한 상태로 합치지 않습니다.
