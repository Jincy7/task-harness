# 동일 환경 참고: 2차 -1 복기

출처는 사용자가 2026-10-31에 이 하네스 수정 대화에 제공한 복기입니다.
내용은 사용자 보고(`reported`)이며 공식 요구 원문이나 에이전트의 직접 실행 관측은 아닙니다.
사용자가 같은 환경을 전제로 참고자료 보존을 요청했습니다. 플랫폼 불안정으로 재응시가 결정됐다는 보고가 있습니다.
이 문서는 해당 환경을 다시 준비할 때만 읽습니다. 실행환경 구현을 변경하는 지침이나 모든 저장소에 적용할 요구가 아닙니다.

## 문제와 제출 요구: 사용자 보고

사업장별 구성원 셔틀 배차 웹서비스이며 사용자와 운영자의 로그인이 필요했습니다.
세 단계 중 첫 단계는 구성원의 정류장 선택이었습니다. 나머지 두 단계의 정확한 구분은 기억이 불명확합니다.
운영자가 도착 시간을 정할 수 있고 최종적으로 구성원 1,500명을 실제 배차해야 했다고 보고했습니다.
운영자가 데이터 세트를 바꾸고 정류장을 배정한 뒤 배차를 확정하면, 구성원이 자신의 시간표를 조회하는 흐름입니다.

README에는 상세 요구가 있고 담당자는 알고리즘에 영향을 주는 일부 미확정 기준의 힌트를 주는 방식이었습니다.
“도보 10분은 괜찮고 15분 이상이면 차를 탄다”는 정성적 관찰이 예로 제시됐습니다.
이를 어떤 선택 기준으로 구현하고 기준 때문에 결과가 달라지는 구성원을 어떻게 처리할지는 사용자의 판단이 필요했습니다.
이 관찰에서 정확한 임계값이나 예외 처리 정책까지 확정됐다고 해석하지 않습니다.

DB 사용과 Docker 빌드 제약이 있었고, 제출에는 `AI_COLLABORATE`, `HOW_TO_RUN` 문서와 빌드 가능한 `Dockerfile`이 요구됐습니다.
문서의 확장자와 파일명의 정확한 대소문자는 현재 제공되는 요구 원문에서 확인합니다.
`AI_COLLABORATE` 질문은 다음과 같이 회상했습니다.

1. 까다로운 엣지케이스나 장애 시나리오는 무엇이며 어떻게 수정했는가
2. AI를 다루는 엔지니어로서 가장 중요하게 검증할 것은 무엇이며 이번 과제에서 어떻게 검증했는가
3. AI가 제안한 것 중 실제 바꾼 것과 받아들인 것은 무엇인가

## 구현 중 경험과 추정

| 내용 | 근거 수준과 한계 |
| --- | --- |
| HTTPS와 인증 관련 문제 | 사용자 보고, 구체적인 원인 및 해결 로그 없음 |
| 미리보기 포트 `3000:47100`, Vite 허용 목록 불일치와 빈 화면 | 사용자가 기억한 표기와 원인 설명, 매핑 방향 및 실제 설정 미확인 |
| 내부 바인딩 포트가 무작위로 결정되는 듯함 | 사용자 추정, 현재 실행 계약으로 확정하지 않음 |
| 핫리로드 설정에 많은 시간 사용 | 사용자 보고, 소요 시간 미측정 |
| 최악의 구성원이 출근에 4시간 소요되는 배차 결과 | 사용자 보고, 결과 품질의 상한 검토 필요, 알고리즘 실행 시간과 구분 |
| 프론트를 외부 패키지 없이 처음부터 구현하려는 경향 | 사용자 관찰, 이후에는 재사용과 직접 구현 부담 비교 |
| 백엔드에 FastAPI 사용 | 당시 선택, 이후 모든 프로젝트의 기술 제약은 아님 |
| computer use 금지, Playwright 같은 MCP 사용 가능 | 당시 허용 범위에 관한 사용자 보고, 현재 도구별 권한은 제공 지침으로 확인 |
| Vercel 계열 browser CLI가 유용할 것이라는 의견 | 사용자 제안, 정확한 제품명과 실제 사용은 미확인 |
| 마지막에 커밋 기록 확인 | 사용자 보고, 세부 평가 기준 미확인 |

포트나 허용 목록 값을 복사해 설정하지 않습니다. 원본 오류, 실제 주소와 설정을 확인할 때 참고할 증상으로 사용합니다.
브라우저 자동 검증은 반복 가능한 기능 확인에 사용하고 업무 정책의 타당성 판단까지 대체했다고 주장하지 않습니다.
여러 세션 작업에는 별도 브랜치와 worktree, 최종 통합 근거를 고려하되 실행 자원까지 자동 격리된다고 해석하지 않습니다.

## 당시 서술형 문항: 기억에 따른 요약

아래는 원문을 확보한 고정 문항이 아니며 사용자 복기의 요약입니다. 작업 흐름에 따라 생성되는 문항이라는 사용자 설명을 따릅니다.

1. 스펙에 드러나지 않은 정류장 선택 같은 업무규칙을 무엇으로 판단했고 어떻게 구현했는가
2. 데이터가 진입부터 출력까지 어떻게 흐르며 누가 소유하고 어디에 저장하며 무엇으로 보호하는가
3. 데이터 유효성 요구에서 구현한 것, 구현하지 않은 것과 가정으로 남긴 것은 무엇인가
4. 어떤 분석을 AI에 지시했고 최종 운행 시간에 관한 알고리즘을 어떻게 찾았는가
5. 운영자가 데이터를 바꾸거나 실행 중 다른 요청이 들어오면 어떻게 되는가
6. `AI_COLLABORATE`에 적은 업무규칙 판단에서 무엇을 받아들이거나 버렸고 AI에 어떻게 지시했는가

이 여섯 문장을 다른 저장소에 복제하지 않습니다. [질문 생성 기준](question-design.md)으로 현재 작업에서 중요한 판단을 다시 선택합니다.
문항 수와 시간은 하네스의 기본 연습 설정과 구분하며, 이 복기만으로 실제 제한 시간이 확인됐다고 보지 않습니다.
