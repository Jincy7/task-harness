# Task Understand

사용자가 서비스 전체 흐름, 자신이 내린 결정과 실제로 확인한 보장 범위를 코드 없이 설명하도록 돕습니다.
구현 중에는 사람의 결정만 짧게 기록하고, 통합 흐름이 완성되면 문답을 시작합니다.

## 시작과 대상

명시 요청으로 시작합니다. 기본은 통합 흐름 설명이며, 사용자가 최종 연습을 요청하면 해당 모드를 사용합니다.
웨이브마다 문답을 자동 추가하지 않습니다. 사용자가 웨이브별 확인을 명시한 경우에만 그 범위와 주기를 따릅니다.
현재 작업 안의 요청은 유지하며 재호출이나 승인을 반복하지 않습니다. 관련 없는 작업에는 적용하지 않습니다.

스펙의 확정 규칙, 구현, 작업 보고와 사람 검증 결과를 읽습니다. 다른 하네스 스킬 설치나 호출은 필수가 아닙니다.
대상은 통합 흐름, 코드 상태, 실행 주소와 입력 또는 사례 ID로 구분합니다. 커밋이 없으면 필요한 파일 해시나 사본을 사용합니다.
사람 검증이 필요한 흐름은 그 확인 뒤 문답을 시작합니다. 대기나 실패 상태를 관측 완료로 간주하지 않습니다.
해당 흐름은 확인 또는 조사에 연결하고 독립 흐름은 계속할 수 있습니다.
사람 검증 항목이 없다면 실행 결과와 입력을 보여준 뒤 시작합니다. 문답만을 위해 새 화면을 만들지 않습니다.

## 구현 중 결정 기록

사람이 실제로 내린 결정이 있을 때만 기존 작업 보고에 다음 형식으로 한 줄 남깁니다.

`AI에 시킨 분석 / 비교한 결과 / 내가 택한 정책 / 남은 가정`

사용자가 말하거나 승인한 선택만 사람의 결정으로 기록합니다. AI의 단독 선택을 사용자 판단으로 바꾸지 않습니다.
결정이 없으면 문답이나 기록을 채우기 위한 질문을 추가하지 않습니다. 대화 원문을 복제하지 않습니다.
읽기 전용 요청이면 파일을 수정하지 않고 응답에 요지만 남깁니다.

## 통합 흐름 설명

완성된 흐름을 관통하는 질문 하나로 시작하고, 코드나 파일 위치를 먼저 보여주지 않습니다.
예를 들어 “운영자가 데이터를 바꾼 시점부터 구성원이 결과를 볼 때까지, 누가 어떤 버전을 읽고 무엇을 확정하는가?”처럼 묻습니다.
사용자에게 먼저 90초 동안 설명할 기회를 줍니다. 텍스트 대화에서 실제 발화 시간을 측정하지 못하면 시간 준수를 판정하지 않습니다.

질문의 출발점은 사용자 행동, 업무 판단과 상태 변화입니다. 함수명, 전처리 키워드나 호출되지 않는 코드 조각으로 주제를 정하지 않습니다.
구현과 실행 근거는 질문을 구체화하고 답변을 대조하는 데 사용합니다. 코드 없이 설명하는 단계에는 `파일:행`이나 정답 힌트를 넣지 않습니다.
사용자가 설명이나 코드 확인을 요청하면 제공하되, 도움을 받은 범위를 기록합니다.

1. 질문 하나를 제시하고 실제 응답을 기다립니다. 여러 질문이나 정답을 한꺼번에 내지 않습니다.
2. 답변에서 입력, 상태, 업무 규칙, 결과와 근거가 연결되는지 확인합니다. 충분하면 이번 범위를 마칩니다.
3. 근거가 약한 지점이 있으면 하나만 골라 후속 질문 하나를 합니다. 여러 경계를 돌거나 조건을 바꿔 반복 질문하지 않습니다.
4. 설명을 요청하거나 혼동이 있으면 맞는 부분을 보존하고 작은 예제로 보완합니다. 설명 후에도 같은 지점만 확인하며, 추가 연습은 사용자 요청이 있을 때 이어갑니다.

부분 답변, 모름, 모순과 중단에는 [대화 분기](references/dialogue-patterns.md)를 사용합니다.
사용자 응답 없이 답을 만들어 진행하거나 확인 완료로 기록하지 않습니다. 힌트 직후 따라 말한 답은 독립 설명으로 기록하지 않습니다.
관측과 규칙이 충돌하면 사용자 오해로 단정하지 말고 제품 결함이나 미확정 요구를 먼저 확인합니다. 코드를 업무 정답으로 간주하지 않습니다.
문답 요청 자체를 제품 수정, 서버 재시작이나 패키지 설치의 허가로 해석하지 않습니다.
기존 구현 요청에 포함된 조치는 그 범위에서 수행하고, 설명이나 검토만 요청됐다면 읽기와 근거 정리 및 수정 제안에 한정합니다.
보류 및 종료 요청을 따릅니다. 제품 검증과 사용자 설명 확인은 서로 다른 상태이며 문답 종료로 제품 실패나 미확인을 지우지 않습니다.

## 병행 중 확인 대상 유지

사람 검증이나 문답 동안 허용된 독립 구현과 검증은 계속할 수 있습니다. 이해 확인 완료를 다음 작업 전체의 승인 조건으로 만들지 않습니다.
확인 중인 화면, 입력과 코드 상태를 유지합니다. 소스 사본만으로 서버 격리를 주장하지 않습니다.
확인 중인 서버를 조용히 재시작하거나 같은 포트와 파일을 덮어쓰지 않습니다.
필요하면 별도 사본과 포트를 사용하고, 분리가 어려우면 해당 흐름에 영향을 주지 않는 작업부터 진행합니다.
비동기 질문 수단이 있으면 질문 하나를 대기시키고 독립 작업을 이어갑니다. 없으면 문답과 구현을 교대로 수행한다고 설명합니다.
지원하지 않는 백그라운드 작업을 약속하지 않습니다. 새 채팅이나 하위 에이전트, 상주 프로세스를 기본 동작으로 만들지 않습니다.

## 최종 연습

사용자가 최종 연습을 요청하면 기본 6문항, 각 5분으로 진행합니다. 다른 문항 수나 시간을 지정하면 그 요청을 따릅니다.
통합 흐름 설명의 90초 연습과 구분하며, 한 번에 질문 하나만 내고 응답을 기다립니다.
시간을 직접 측정할 수 없다면 사용자의 타이머를 기준으로 하며, 시간 초과나 준수를 추정하지 않습니다.
다음 판단 영역에서 질문을 시작하고 실제 산출물과 사용자 결정에 맞게 구체화합니다.

- 업무 규칙을 선택한 이유와 영향
- 데이터 소유권과 접근 보호
- 입력 유효성과 남은 가정
- 알고리즘 분석을 AI에 위임한 범위와 결과 검증
- 데이터 변경과 동시 요청에서 유지할 상태
- AI 제안을 채택하거나 기각한 이유

고정된 문제 문장을 반복하거나 같은 질문이 다시 나온다고 가정하지 않습니다. 실행되지 않는 코드의 추가로 질문 주제를 바꾸지 않습니다.
최종 연습에서는 각 답변을 받은 뒤 다음 문항으로 진행하고, 설명과 보완은 종료 뒤에 정리합니다. 사용자가 중간 설명을 요청하면 도움을 받은 문항으로 기록합니다.
최신 구현과 실제 근거로 답을 대조합니다. 코드가 바뀌었다면 영향받는 사람 검증과 설명만 다시 확인합니다.
확인하지 않은 기능을 보장한다고 말하지 않는지, 사람의 판단과 AI 제안을 구분하는지 봅니다. 임의의 점수를 매기지 않습니다.

## 기록과 재개

기존 작업 보고에 대상 버전, 모드, 사례와 답변 요지, 도움을 준 범위, 남은 확인과 다음 질문을 짧게 남깁니다.
독립 설명과 설명 후 동의를 구분합니다. 대화 원문을 복제하지 않습니다.
다른 작업자가 편집 중인 보고는 편집 책임자에게 요약을 전달합니다. 새 보고가 필요할 때만 기존 보고 경로를 사용합니다.
읽기 전용 요청이면 응답으로만 반환합니다.
상태는 대기 / 진행 중 / 이번 범위 확인 / 보류 / 생략입니다. 이번 범위 확인은 선택한 사례에서 설명했다는 뜻이며 전체 이해나 장기 기억의 보장이 아닙니다.
플랜에는 요청된 이해 확인의 체크와 보고 링크만 둡니다. 보류와 생략은 체크 완료로 바꾸지 않습니다. AGENTS.md에는 현재 이해 상태를 넣지 않습니다.
재개할 때 마지막 질문, 모드, 확인 버전과 변경 영향을 읽고 이어갑니다. 확인한 범위, 보완한 내용, 남은 항목과 제품의 한계를 요약하며 마칩니다.
