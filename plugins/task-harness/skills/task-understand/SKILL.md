# Task Understand

사용자가 관측한 동작과 내부 흐름을 연결해 설명하도록 돕습니다. 웨이브는 직접 확인할 수 있는 기능 흐름 하나이며, 커밋마다 문답을 추가하지 않습니다.

## 시작과 대상

명시 요청으로 시작합니다. 이번 웨이브만 확인할지, 현재 작업의 매 웨이브와 마지막을 확인할지 사용자 요청과 기록에서 정합니다. 매 웨이브 확인을 요청했다면 해당 작업 안에서는 재호출이나 승인을 반복하지 않습니다. 관련 없는 작업에는 적용하지 않습니다.

스펙의 확정 규칙, 구현, 작업 보고와 사람 검증 결과를 읽습니다. 다른 하네스 스킬 설치나 호출은 필수가 아닙니다.
대상은 웨이브, 코드 상태, 실행 주소와 입력 또는 사례 ID로 구분합니다. 커밋이 없으면 필요한 파일 해시나 사본을 사용합니다.
사람 검증이 필요한 흐름은 그 확인 뒤 문답을 시작합니다. 대기나 실패 상태를 관측 완료로 간주하지 않습니다. 해당 흐름은 확인 또는 조사에 연결하고 독립 흐름은 계속할 수 있습니다.
사람 검증 항목이 없다면 실행 결과와 입력을 보여준 뒤 시작합니다. 문답만을 위해 새 화면을 만들지 않습니다.

## 한 질문씩 진행

현재 웨이브에서 중요한 흐름과 경계 2~3개부터 선택하되 개수 채우기를 목표로 삼지 않습니다. 방금 본 결과에서 시작해 입력, 상태 변화, 업무 규칙, 출력과 근거를 연결합니다.

1. 한 가지 판단을 묻는 질문 하나를 제시하고 응답을 기다립니다. 여러 질문, 정답과 후속 문제를 한꺼번에 내지 않습니다.
2. 응답이 충분하면 어떤 판단이 맞는지 짧게 확인하고 다음 경계로 이동합니다. 결과만 맞으면 이유 하나를 더 묻습니다.
3. 부족하면 맞는 부분을 보존하고 혼동된 부분만 짧게 설명합니다. 작은 예제를 보여준 뒤 조건이나 숫자를 바꾼 사례 하나로 다시 묻습니다.
4. 사용자 응답이 오기 전에는 답을 만들어 진행하거나 확인 완료로 기록하지 않습니다. 설명을 요청하면 먼저 설명하고 새 사례로 적용을 확인합니다.

부분 답변, 모름, 모순과 중단에는 [대화 분기](references/dialogue-patterns.md)를 사용합니다. 자유 응답을 기본으로 하고 선택지나 힌트는 필요할 때 제공합니다.
필드명이나 함수명 기억보다 업무 의미와 이유를 봅니다. 정답 직후 따라 말한 응답과 힌트로 도운 응답을 독립 적용으로 기록하지 않습니다.
관측과 규칙이 충돌하면 사용자 오해로 단정하지 말고 제품 결함이나 미확정 요구를 먼저 확인합니다. 코드를 업무 정답으로 간주하지 않습니다.
문답 요청 자체를 제품 수정, 서버 재시작이나 패키지 설치의 허가로 해석하지 않습니다. 기존 구현 요청에 포함된 조치는 그 범위에서 수행하고, 설명이나 검토만 요청됐다면 읽기와 근거 정리 및 수정 제안에 한정합니다.
같은 설명을 끝없이 반복하지 않습니다. 설명 방식을 바꾸거나 남은 확인으로 두고, 보류 및 종료 요청을 따릅니다.

## 병행 중 확인 대상 유지

사용자가 사람 검증이나 문답을 하는 동안 허용된 독립 구현과 검증은 계속할 수 있습니다. 이해 확인 완료를 다음 작업 전체의 승인 조건으로 만들지 않습니다.
실행 중인 화면, 입력과 코드 상태가 어느 대상인지 확인합니다. 소스 사본만으로 서버 격리를 주장하지 않습니다.
확인 중인 서버를 조용히 재시작하거나 같은 포트와 파일을 덮어쓰지 않습니다. 필요하면 별도 사본과 포트를 사용하고, 분리가 어려우면 해당 흐름에 영향을 주지 않는 작업부터 진행합니다.
비동기 질문 수단이 있으면 질문 하나를 대기시키고 독립 작업을 이어갑니다. 없으면 문답과 구현을 교대로 수행한다고 설명합니다. 지원하지 않는 백그라운드 작업을 약속하지 않습니다.
새 채팅이나 하위 에이전트, 상주 프로세스를 이 스킬의 기본 동작으로 만들지 않습니다. 규칙 변경이나 결함은 의존 작업에만 연결합니다.

## 최종 점검

웨이브별 확인을 적용한 작업은 마지막에 최신 구현을 대상으로 최종 점검합니다. 사용자가 최종 점검만 요청해도 직접 시작할 수 있습니다.
코드가 바뀌었으면 영향받는 사람 검증과 설명만 다시 확인합니다. 이전 버전의 확인을 최신 버전으로 옮기지 않습니다.
여전히 필요한 사람 검증이 남았다면 먼저 준비하고, 확인된 범위만 문답합니다. 최종 모드에서도 한 번에 질문 하나입니다.

- 입력부터 결과와 근거까지 여러 웨이브를 연결한 흐름
- 이전에 혼동한 규칙을 다른 순서나 조건에 적용하는 사례
- 실패와 복구, 중복 요청 등 실제 요구에 해당하는 경계
- 검증한 범위, 미확인과 설계만 있는 기능의 구분

정해진 문제 목록을 반복하거나 점수를 매기지 않습니다. 제품 검증과 사용자 설명 확인은 서로 다른 상태입니다. 문답 종료로 제품 실패나 미확인을 지우지 않습니다.

## 기록과 재개

기존 작업 보고의 이해 확인 항목에 대상, 규칙 ID, 사례와 답변 요지, 도움을 준 범위, 변형 사례 결과, 남은 확인과 다음 질문을 짧게 남깁니다. 대화 원문을 복제하지 않습니다.
다른 작업자가 편집 중인 보고는 편집 책임자에게 요약을 전달합니다. 새 보고가 필요할 때만 기존 보고 경로를 사용합니다. 읽기 전용 요청이면 응답으로만 반환합니다.
상태는 대기 / 진행 중 / 이번 범위 확인 / 보류 / 생략입니다. 이번 범위 확인은 선택한 사례에서 설명했다는 뜻이며 전체 이해나 장기 기억의 보장이 아닙니다.
플랜에는 웨이브 이해 확인과 최종 점검의 체크 및 보고 링크만 둡니다. 보류와 생략은 체크 완료로 바꾸지 않습니다. AGENTS.md에는 현재 이해 상태를 넣지 않습니다.
재개할 때 마지막 질문, 모드, 확인 버전과 변경 영향을 읽고 이어갑니다. 확인한 범위, 보완한 내용, 남은 항목과 제품의 한계를 요약하며 마칩니다.
