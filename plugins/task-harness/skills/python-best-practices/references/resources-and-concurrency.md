# 자원과 동시성

## 자원 수명

파일, 연결, 임시 디렉터리의 소유자와 종료 시점을 정합니다. `with`가 실제로 무엇을 정리하는지 확인합니다. 예를 들어 `sqlite3.Connection`의 컨텍스트 매니저는 트랜잭션을 처리하지만 연결을 닫지는 않으므로 연결 소유자가 종료를 보장합니다. 호출자가 넘긴 연결은 소유권을 이전한다는 계약이 없으면 임의로 닫지 않습니다.

실패나 취소 경로에서도 `finally` 또는 적절한 컨텍스트 매니저로 정리합니다. 자원 정리 오류가 원래 실패를 가리는지도 확인합니다.

## async와 병렬 처리

- async 흐름의 동기 네트워크 요청과 파일 작업이 이벤트 루프를 막는지 확인합니다. 필요하면 비동기 클라이언트나 제한된 작업 스레드를 사용하며, CPU 작업은 별도 측정과 실행 전략으로 판단합니다.
- 자식 작업의 완료, 예외와 취소를 누가 회수하는지 명시합니다. 지원 버전이 맞으면 `TaskGroup` 같은 구조화된 방식으로 수명을 묶습니다. fire-and-forget은 강한 참조, 오류 처리와 종료 절차가 있을 때만 사용합니다.
- `CancelledError`를 성공이나 일반 재시도로 바꾸지 않습니다. 정리가 끝나면 취소를 전파합니다. 스레드로 넘긴 작업은 await가 취소되었다는 이유만으로 중단됐다고 가정하지 않습니다.
- 동시 요청 수, 큐 크기, 타임아웃을 제한합니다. 작은 입력에서 통과했다는 이유로 무제한 `gather`가 안전하다고 판단하지 않습니다. 공유 연결이나 상태의 동시 접근 규칙을 확인합니다.

## 성능 판단

실제 입력 규모, 시간과 메모리를 먼저 측정합니다. 반복 I/O, 중복 계산, 불필요한 전체 자료 적재를 찾고 현재 병목만 수정합니다. 스트리밍과 배치는 순서, 오류 보고와 트랜잭션 계약을 유지할 때 적용합니다. 캐시에는 무효화 기준과 크기 제한이 필요합니다.

취소, 타임아웃, 부분 실패, 반복 호출 후 자원 수를 변경 범위에 맞게 검증합니다. 근거 없이 async 전환이나 병렬 처리를 성능 개선으로 보고하지 않습니다.
