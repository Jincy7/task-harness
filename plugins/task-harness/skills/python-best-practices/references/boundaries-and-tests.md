# 경계와 테스트

## 입력과 업무 규칙

- 타입 힌트는 런타임 검증을 대신하지 않습니다. 외부 JSON, 환경 변수, 파일 입력은 경계에서 형식과 의미를 확인합니다. 누락, 빈 문자열, `null`, 0을 계약에 맞게 구분합니다.
- 정수만 허용하는 계약에서는 Python의 `bool`이 `int`의 하위 타입인 점을 확인합니다. 입력을 무조건 문자열이나 숫자로 변환해 오류를 숨기지 않습니다.
- 시간대, 금액의 단위와 반올림, 정렬과 동률 규칙을 명시합니다. 기존 계약의 값을 바꾸는 정규화는 피합니다.
- 업무 판단은 가능한 한 I/O와 분리해 작은 입력으로 검증합니다. 한 번 쓰는 함수에 범용 계층을 추가하지 않습니다. 가변 기본 인자와 요청 사이에 공유되는 상태를 확인합니다.

## 예외와 저장

- 처리할 수 있는 구체적인 예외를 잡고, 변환할 때는 원인 연결을 유지합니다. 예상하지 못한 오류를 성공 값이나 빈 결과로 바꾸지 않습니다. 외부 응답과 로그에는 비밀값이나 내부 스택을 노출하지 않습니다.
- SQL 값은 바인딩합니다. 테이블명이나 정렬 키 같은 식별자는 허용 목록에서 선택합니다. 데이터 변경과 관련 검증은 필요한 원자성 경계 안에 둡니다.
- 실패 시 롤백, 유일성 제약, 중복 요청과 재시도 후 상태를 확인합니다. 멱등성이 없는 쓰기를 자동 재시도하지 않습니다. 재시도가 필요하면 대상 오류, 횟수와 시간 제한을 정합니다.
- 테스트용 경로와 시간을 주입할 수 있게 하되 현재 실패 경계에 필요한 범위만 분리합니다. import만으로 DB 생성이나 네트워크 요청이 일어나지 않게 합니다.

## 검증할 관측

| 변경 경계 | 확인할 결과 |
| --- | --- |
| 입력과 변환 | 정상, 누락, 빈 값, 잘못된 타입과 경계값의 결과 |
| 저장 | 성공 후 재조회, 중간 실패 후 미반영, 중복 요청의 결과 |
| 예외 변환 | 오류 종류, 사용자 응답과 원인 보존 |
| 테스트 격리 | 임시 파일과 DB 사용, 실행 순서 독립, 자원 정리 |

실제 DB나 HTTP 어댑터의 결함을 찾는 테스트에서는 그 경계를 전부 mock으로 바꾸지 않습니다. 외부 서비스나 시간을 통제할 필요가 있는 지점에만 대역을 둡니다. 구현의 내부 호출 횟수보다 반환값과 저장 상태를 확인합니다.

공식 근거: [타입 힌트의 런타임 한계](https://docs.python.org/3/library/typing.html), [SQLite 바인딩과 트랜잭션](https://docs.python.org/3/library/sqlite3.html). 지원 버전에 맞는 문서를 확인하며, 이 지침을 적용할 때 외부 문서 전체를 읽을 필요는 없습니다.
