# 규칙 구분과 정정

업무 결과를 바꾸는 모호함이나 설명 충돌이 있을 때 필요한 부분만 사용합니다. 단순 수정에 규칙표나 별도 원장을 요구하지 않습니다.

| 기존 수용 조건에 연결할 정보 | 내용 |
| --- | --- |
| 판단 질문 | 무엇을 결정하는 규칙인지 |
| 입력과 기준 | 사용하는 사실과 상태, 확정 근거 또는 가정 |
| 유지되는 것 | 다른 조건이 바뀌어도 보존할 값과 의미 |
| 경계 사례 | 혼동을 드러내는 작은 입력과 기대 결과 |

소속과 발생 시각, 후보 선택과 유효성, 관측값과 최종 확정처럼 다른 질문을 하나의 상태로 합치지 않습니다. 필드 이름만으로 업무 규칙을 결정하지 않습니다.
예를 들어 등록 그룹을 유지하는 규칙이면 이벤트 시각만 바꿨을 때 그룹이 이동하는지 확인합니다. 새 결과를 추가하는 사례는 시각만 바꾸는 사례와 분리합니다.

규칙을 정정하면 현재 스펙의 수용 조건 본문을 갱신합니다. 작업 보고에는 이전 가정, 정정 근거와 영향받는 구현 및 회귀 사례를 연결합니다.
면담 원문과 과거 실행은 보존하고, 이전 통과를 현재 통과로 바꾸지 않습니다. 정정 내용을 단계별 덧붙임에만 두어 현재 규칙을 조합해서 읽게 하지 않습니다.
새 기대값은 확인된 규칙에서 도출하며, 규칙 변경과 구현 결함 수정을 구분합니다. 구현 변경이 허용되지 않은 요청이면 영향과 후속 검증만 제시합니다.

## 정성적 관찰에서 정책 결정까지

제공된 요구에서 확정된 부분은 다시 질문하지 않습니다. 담당자에게는 결과를 바꾸는 미확정 기준을 묻습니다.
답변은 확정 요구, 현장 관찰, 사용자가 선택한 정책, 남은 가정으로 구분합니다.
예를 들어 “보통 10분은 괜찮다”는 관찰만으로 10분 초과를 모두 제외하는 정책이 확정된 것은 아닙니다.

후보 정책을 같은 입력에 적용했을 때 결과가 바뀌는 대상, 수와 예외를 비교합니다.
제외된 대상의 처리, 경계값과 동률, 단위 및 시간 기준 중 결과를 바꾸는 조건을 함께 정합니다.
담당자에게 최종 정책을 대신 정하도록 반복 질문하지 않습니다. 사용자의 판단이 필요한 영향은 비교 근거와 함께 제시합니다.
위임받은 범위 안에서 에이전트가 선택한 정책은 에이전트의 선택으로 기록합니다. 사용자가 결정했다고 바꾸지 않습니다.

계산이나 배정에서는 개선하려는 목적과 반드시 지킬 제약을 구분합니다.
평균 개선이 개별 대상의 과도한 부담을 허용하는지 확인하고, 허용 상한이 미정이면 미결 조건으로 남깁니다.
근거 없는 숫자를 필수 제약으로 만들지 않습니다. 제한 때문에 해가 없을 때의 처리도 현재 수용 조건에 포함합니다.

## 상태가 이어지는 작업의 계약

입력부터 결과까지 여러 역할이나 저장 상태를 거치면, 현재 흐름의 수용 조건에 다음을 연결합니다.

- 데이터의 작성자, 저장 위치, 읽거나 변경할 수 있는 주체
- 입력 버전, 계산 결과와 확정 상태의 연결
- 입력 변경 시 진행 중 작업과 이전 결과의 처리
- 중복 또는 동시 요청에서 허용되는 최종 상태
- 입력 유효성의 확인 위치, 거절 또는 보정 정책, 확인하지 않은 가정

이 정보가 이미 스펙에 있으면 참조합니다. 단순 수정에 새 상태표나 전체 설계를 요구하지 않습니다.
