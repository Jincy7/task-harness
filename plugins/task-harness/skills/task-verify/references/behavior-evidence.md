# 행동과 실패 근거

## 한 조건 변경과 유지 조건

혼동하기 쉬운 계산이나 상태 규칙은 한 조건을 바꿨을 때 변하는 결과와 유지되는 결과를 함께 확인합니다. 기존 사례 표를 재사용하며 모든 기능에 새 표를 만들지 않습니다.

| 사례 | 변경 | 고정 | 기대 |
| --- | --- | --- | --- |
| 소속과 시각 | 이벤트 시각 | 등록 그룹과 업무 값 | 등록 기준 그룹 유지 |
| 완료와 진행 | 진행 중 작업 추가 | 기존 유효 완료 | 규정에 따라 완료 관측 유지, 진행 상태 별도 표시 |
| 선택과 유효성 | 최신 후보의 유효성 | 선택 순서와 이전 후보 | 규정에 없는 이전 값 대체 금지 |
| 구성비와 보정 | 관측 구성비 | 제품별율과 비교용 기준 가중치 | 원래 전체율은 변할 수 있고 같은 기준의 보정율은 유지 |

이는 검증 설계의 예시입니다. 실제 기대 동작은 프로젝트 규칙에서 정합니다. 마지막 사례에서 기준 가중치까지 바꾸면 보정율 유지가 일반적으로 성립하지 않습니다.
기대값은 작은 독립 계산, 결정표나 직접 상태 조회에서 얻습니다. 구현의 출력 복사는 독립 기대값이 아닙니다. 변경 전후 출력 동일성은 기존 결함도 보존하므로 요구에 따른 검사를 대신하지 않습니다.

## 사람 확인 준비

대상 버전과 주소, 시작 상태, 입력, 조작, 기대 결과 및 초기화 방법을 연결합니다. 사람이 만들기 어려운 상태는 기존 fixture나 제어 가능한 대기로 준비할 수 있습니다.
실제 앱 경로를 재사용하고 주입 및 대역의 경계를 밝힙니다. 브라우저 응답 전달 보류는 서버 처리 지연이나 서버 멱등성을 증명하지 않습니다. DOM 대역 결과를 실제 레이아웃과 스크롤 관측으로 확대하지 않습니다.
준비에 코드 수정이 필요한데 검토만 요청받았다면 방법을 제안하고 수정하지 않습니다. 사용자 확인은 해당 동작의 사용자 보고로 유지합니다.

## 조사 가능한 실패

검증기를 만들거나 수정하는 범위에서 적용합니다. 기존 실행기와 assertion이 정보를 제공하면 새 형식이나 범용 실행기를 만들지 않습니다.

| 보존할 정보 | 목적 |
| --- | --- |
| 실행 및 사례 ID, 코드와 입력 식별 | 대상 재현 |
| 명령, 작업 위치, 종료 코드, timeout과 signal | 실행 문제와 제품 실패 구분 |
| 안전한 stdout와 stderr의 원문 위치 | 한 스트림만 남겨 진단을 잃지 않도록 보존 |
| 기대값과 실제값의 위치 및 비교 규칙 | 타입, 순서, 허용 오차 차이 해석 |
| 첫 불일치 JSON 경로나 구조화 assertion | 긴 결과에서 조사 시작점 제공 |
| 수집 상태와 누락 영향 | complete / partial / unavailable 및 영향받는 주장 |

원문은 개인 로컬 실행 경로에 보관하고 비밀값이나 불필요한 개인정보를 제외합니다. 잘리거나 제외한 범위도 표시합니다. 보고에는 요약과 위치만 남깁니다.
업무 stdout 계약과 원래 종료 코드를 유지합니다. stdout에 오류가 있는데 stderr만 저장하는 방식은 피합니다. 중계 명령의 성공을 실제 실행 성공으로 대체하지 않습니다.
외부 검사가 기대값이나 전체 출력을 주지 않으면 그 한계를 기록합니다. 원래 실패는 유지하고 정확한 원인은 미확정으로 둡니다. 다른 검사 통과로 원래 실패를 덮거나 근거 없는 불일치 경로를 만들지 않습니다.
수집기 호환성이나 외부 평가 시스템의 출력 폐기는 해당 시스템의 별도 수정 범위입니다. 지침을 작성했다는 이유로 수집이 복구됐다고 보고하지 않습니다.

## 결과 품질과 전체 대상

계산이나 배정 결과는 작은 독립 기대값과 실제 요구 규모에서 각각 확인합니다.
입력 대상 수와 정상 처리, 명시적 예외의 합을 대조하고 누락과 중복을 확인합니다.
평균이나 전체 합계와 함께 가장 불리한 대상의 경로 및 수치를 봅니다. 처리 시간이 짧다는 이유로 업무 결과의 품질을 통과시키지 않습니다.
필수 제약을 어긴 결과는 실패로, 허용 상한이 정해지지 않은 결과의 적합성은 미확인으로 구분합니다.
임의의 허용값을 만들어 통과시키거나 후보 중 상대적으로 낫다는 이유로 수용 조건을 충족했다고 판단하지 않습니다.

## 데이터 변경과 동시 요청

프로젝트에 해당하는 사례만 선택하고, 기대 정책은 스펙에서 가져옵니다.

| 행동 | 대조할 근거 |
| --- | --- |
| 계산 중 입력 교체 | 계산이 읽은 버전, 취소 또는 완료 후 처리와 조회 버전 |
| 이전 계산 결과 확정 | 확정 시점 버전 검사, 거절 또는 허용 정책과 실제 저장 |
| 같은 결과에 동시 확정 요청 | 각 응답과 최종 저장 상태, 중복 생성이나 부분 확정 여부 |
| 잘못된 입력 또는 일부 행 제외 | 검사 위치, 거절 또는 보정 근거, 제외 수와 결과 영향 |

한 요청씩 순차 실행한 결과만으로 동시성 통과를 선언하지 않습니다.
실제 겹치는 요청을 만들 수 없었다면 해당 조건은 미확인으로 남깁니다.

## 자동 UI 검증과 역할별 흐름

현재 사용 가능한 도구와 허용 범위를 확인한 뒤 반복 가능한 UI 검증에는 브라우저 자동화를 사용합니다.
특정 MCP나 CLI를 필수로 요구하지 않으며 도구가 없으면 가능한 API 검증과 남은 사람 확인을 구분합니다.
화면의 업무 의미 판단과 사용성 의견을 자동 조작 성공으로 대체하지 않습니다.

역할이 나뉜 앱에서는 별도 인증 세션으로 작성 또는 확정 → 다른 역할의 조회를 이어서 확인합니다.
본인 데이터 조회, 타인 데이터 접근 거부와 권한 없는 변경 거부를 실제 앱 경로에서 확인합니다.
화면 표시와 API 응답 및 저장 결과를 필요한 범위에서 대조하고, 테스트 대역이 있는 경계는 명시합니다.
