# Task Agents

`AGENTS.md`를 문서 작성 방법과 스킬 사용 시점을 찾는 짧은 룰북 지도로 작성합니다. 구현 현황, 테스트 결과, 환경 상태는 해당 기록의 원본에서 관리합니다.

## 적용 범위 확인

사용자 요청, 적용되는 상위 경로와 대상 디렉터리의 `AGENTS.md`, `AGENTS.override.md`, 현재 제공된 지침을 먼저 읽습니다. 하위 지침은 해당 영역을 다룰 때 확인합니다. 같은 디렉터리의 override를 지우거나 바꾸어 새 지침을 강제로 적용하지 않습니다.

기존 사용자 규칙과 문서 경로를 보존하며 필요한 부분만 수정합니다. 룰북 지도로 정리하더라도 보존, 보안, 업무 규칙을 임의 삭제하지 않습니다. 별도 규칙 문서로 옮길 필요가 있으면 원래 의미와 적용 범위를 유지하고 직접 링크합니다. 전역 사용자 지침은 수정하지 않습니다.

## 지도 작성

README, 기존 docs와 작업 장부, 실제 사용 가능한 스킬 목록을 확인합니다. [지침 템플릿](references/agents-template.md)에서 필요한 부분만 사용합니다.

1. 문서에 무엇을 어디에 기록할지 정합니다. 요구와 수용 조건은 스펙, 구현 체크리스트는 플랜, 실행 결과와 이상 상황의 원인 및 조치는 별도 작업 보고, 결정 이유는 ADR, 관계 그림은 다이어그램에 둡니다. 정보별 원본은 한 곳에 두고 링크합니다.
2. 실행 방법은 README나 기존 실행 안내로 연결합니다. 명령 목록, 실행 성공 이력, 현재 버전, 구현 여부, 파일이나 테스트의 부재 목록을 AGENTS.md에 복제하지 않습니다. 오래된 사실은 원본과 대조해 정정하고 필요한 과거 근거는 시점과 함께 기존 기록에 보존합니다.
3. 스킬마다 사용 시점과 진입점을 한 줄로 적습니다. 실제 설치되었거나 로컬에서 읽을 수 있는 스킬만 연결합니다. 플러그인 호출명은 환경에서 확인한 이름을 사용하고, 로컬 스킬은 상대 경로로 연결합니다. 미설치 스킬의 호출을 요구하지 않습니다.
4. 범위가 불명확하면 scope, 구현할 흐름이 확정되면 build, 수용 조건 대조는 verify, 문서 정리는 docs, 이 지도 정리는 agents입니다. Python과 React 지침은 해당 코드의 작성 또는 검토에만 연결합니다. 매번 모든 스킬을 순서대로 호출하게 만들지 않습니다.

사람 검증 뒤 웨이브별 이해 확인이나 마지막 통합 문답을 명시 요청한 경우에는 사용 가능한 task-understand를 연결합니다. 현재 작업 안의 반복 요청은 유지하되, 관련 없는 작업에서 자동 시작하도록 지도에 쓰지 않습니다.

기존 `docs/spec`, `docs/plan`, `WORK.md`를 유지합니다. 경로가 없으면 예정임을 표시하거나 생략하며, 지도 작성만을 위해 빈 문서나 디렉터리를 생성하지 않습니다. 스킬 상세 규칙을 지도에 통째로 복사하지 않습니다.

## 경계와 종료

문서만 요청받았다면 제품 구현이나 스킬 설치를 시작하지 않습니다. 읽기 전용 요청에는 초안과 차이만 반환합니다. 지침 파일은 sandbox, 네트워크, 승인 권한을 부여하지 않습니다. 권한 완화, 인증 복사, 전역 설정 변경을 해결책으로 넣지 않습니다.

변경 전후의 사용자 규칙, 실제 링크, 스킬 사용 조건과 적용 범위를 대조합니다. 변경 파일과 원본 위치, 미확인 링크나 호출을 반환합니다. 파일 작성 완료와 새 세션의 실제 지침 로딩 확인을 구분합니다.
