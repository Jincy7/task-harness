# Task Agents

다음 작업자가 저장소의 목적, 진입점, 실행 방법, 문서 위치와 제약을 빠르게 찾도록 짧은 `AGENTS.md`를 작성하거나 갱신합니다.

## 적용 범위 확인

대상 작업 경로와 사용자 요청을 확인하고, 적용되는 상위 경로와 대상 디렉터리의 `AGENTS.md`, `AGENTS.override.md`, 현재 제공된 지침을 먼저 읽습니다. 하위 경로의 지침은 해당 영역을 다룰 때 확인합니다. 같은 디렉터리에서는 override가 우선하므로 새 `AGENTS.md`를 만들었다는 사실만으로 적용됐다고 판단하지 않습니다.

기존 사용자 규칙과 문서 경로를 보존하며 필요한 부분만 수정합니다. 템플릿으로 전체 파일을 교체하지 않습니다. 충돌이 있으면 위치와 범위를 확인하고, 사용자 결정이 필요한 규칙만 질문합니다. override를 지우거나 바꾸어 지침을 강제로 적용하지 않습니다. 현재 작업의 저장소 지침 요청을 전역 사용자 지침 수정으로 확대하지 않습니다.

## 근거 수집과 작성

코드 진입점, 설정 파일, 패키지 스크립트, 기존 README와 docs를 읽습니다. 새 구성이 필요한 경우에만 [지침 템플릿](references/agents-template.md)을 사용합니다. 다음 다섯 항목 중 확인한 내용을 짧게 기록합니다.

1. 저장소 목적과 주요 코드 진입점
2. 설정이나 파일에서 확인한 실행, 검증 명령과 작업 위치
3. 문서 경로와 정보별 원본 위치
4. 현재 흐름 구현, 선택적 위임, 근거에 따른 완료 판단 원칙
5. 해당 저장소와 세션에 실제 적용되는 제약

명령은 다음과 같이 구분합니다.

| 근거 | 기록 |
| --- | --- |
| 설정에서 명령 정의만 확인 | 설정 확인, 미실행 |
| 실제 실행하고 종료 결과 확인 | 실행 시점, 종료 결과와 확인한 범위 |
| 명령이나 스크립트 부재 | 없다고 기록하거나 생략 |
| 실행 환경 또는 결과 불명 | 미확인과 필요한 확인 방법 |

관례만으로 `npm test` 같은 명령을 만들지 않습니다. 문서를 채우기 위해 설치, 배포, 데이터 변경 명령을 실행하지 않습니다. 문법 검사 성공을 기능 테스트 성공으로 기록하지 않습니다. 과거 성공 기록에는 당시 범위와 시점을 유지합니다.

기존 docs 경로를 사용하고 정보별 원본을 연결합니다. 구조가 없으면 스펙은 `docs/specs`, 작업과 검증은 `docs/plans`, 결정 이유는 `docs/adr`, 그림은 `docs/diagrams`를 기본 후보로 삼습니다. 지침 작성만 요청받았다면 이 폴더나 문서를 자동 생성하지 않습니다. 계획된 경로는 예정으로 표시하고 실제 경로와 구분합니다.

## 경계와 종료

지침 파일은 sandbox, 네트워크, 승인 권한을 부여하지 않습니다. 권한 완화, Codex 업데이트, 인증 복사, 외부 서비스 연결을 해결책으로 추가하지 않습니다. 다른 환경의 제약을 근거 없이 이 저장소의 규칙으로 옮기지 않습니다. 비밀값이나 개인 설정을 문서에 복사하지 않습니다.

문서만 요청받았다면 제품 구현을 시작하지 않습니다. 읽기 전용 요청에서는 파일 변경 대신 초안과 차이를 응답으로 반환합니다. 다른 하네스 스킬의 설치나 호출은 필요하지 않습니다.

완료 전에 변경 전후를 대조하여 기존 규칙 보존, 경로와 명령의 근거, 지침 적용 범위를 확인합니다. 변경 파일, 보존한 규칙, 설정 확인과 실제 실행 결과, override에 따른 적용 한계를 반환합니다. 파일 작성 완료와 새 세션의 실제 지침 로딩 확인을 구분합니다.
