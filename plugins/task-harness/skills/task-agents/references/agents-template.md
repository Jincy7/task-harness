# 룰북 지도 템플릿

대상 저장소에서 확인한 경로와 스킬만 채웁니다. 아래 표의 설명은 실제 링크로 바꾸고 해당하지 않는 행은 생략합니다. 기존 지침 전체를 이 틀로 덮어쓰지 않습니다.

```markdown
# 작업 룰북 지도

## 문서 작성

| 기록할 내용 | 원본 위치 |
| --- | --- |
| 문서 탐색 | 기존 docs 지도 링크 |
| 기대 동작과 수용 조건 | 해당 스펙 링크 |
| 구현할 작업과 완료 체크 | 플랜 체크리스트 링크 |
| 실행 결과, 이상 상황과 해결 근거 | 별도 작업 보고 링크 |
| 중요한 결정과 대안 | 기존 ADR 경로 링크 |
| 구조와 흐름 | 해당 다이어그램 링크 |
| 설치와 실행 방법 | README 또는 실행 안내 링크 |

기존 경로를 유지하고 정보별 원본을 한 곳에 둡니다. 다른 문서에서는 링크와 요구 ID로 참조합니다. 현재 작업에 필요한 문서만 작성합니다. 플랜에는 체크리스트와 관련 링크만 두고, 실행 결과는 작업 보고에 남깁니다. 실제 관측, 과거 보고와 미확인을 구분하고 결과에는 확인 범위를 남깁니다.

## 쓰기 작업의 완료 조건

Git 저장소의 쓰기 작업에는 스킬 호출 여부와 관계없이 이 조건을 적용합니다.
사용자 동작 하나나 수정 목적 하나를 구현하고 관련 검증을 통과하면 현재 작업의 diff를 확인합니다.
현재 작업의 구현, 필요한 테스트와 문서만 stage하고 staged diff를 확인한 뒤 로컬 커밋합니다.
다음 작업으로 넘어가기 전에 브랜치, 커밋 SHA와 검증 결과를 보고합니다.
커밋이 막히면 실패 이유와 미커밋 변경을 보고하며, 커밋한 것처럼 완료 처리하지 않습니다.
사용자의 커밋 보류 또는 금지 지시를 따르고 기존 사용자 변경을 임의로 포함하거나 되돌리지 않습니다.
Git이 없으면 이 조건만을 이유로 저장소를 만들지 않습니다. 원격 push와 배포는 별도 승인 범위를 따릅니다.

## 스킬 선택

| 필요한 작업 | 사용할 스킬 또는 로컬 지침 |
| --- | --- |
| 요구 정리와 작업 분해 | 확인한 task-scope 진입점 |
| 확정된 흐름 구현 | 확인한 task-build 진입점 |
| 수용 조건과 실제 결과 대조 | 확인한 task-verify 진입점 |
| 명시 요청한 통합 흐름 설명과 최종 연습 | 확인한 task-understand 진입점 |
| 문서 정리와 다이어그램 | 확인한 task-docs 진입점 |
| 이 지도 정리 | 확인한 task-agents 진입점 |
| Python 구현 또는 코드 검토 | 확인한 python-best-practices 진입점 |
| React 구현 또는 코드 검토 | 확인한 react-best-practices 진입점 |

현재 작업에 필요한 지침만 읽습니다. 작은 수정은 해당 작업으로 바로 시작하며, 모든 스킬의 순차 호출을 요구하지 않습니다.
```

기존 사용자 규칙은 적용 범위를 유지해 보존하거나 원본 규칙 문서에 직접 연결합니다. 실행 명령 표, 미구현 목록, 테스트 통과 이력은 이 지도에 추가하지 않습니다.
