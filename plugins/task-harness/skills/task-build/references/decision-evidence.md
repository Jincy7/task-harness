# 분석과 변경 계약의 구현 근거

계산 방식이나 데이터 변경 정책을 구현할 때 필요한 부분만 사용합니다. 기존 수용 조건과 작업 보고를 원본으로 유지합니다.

## 분석을 맡길 때

AI에 분석을 지시하면 입력 데이터와 규모, 목적함수, 필수 제약, 비교할 기준 및 확인할 출력을 함께 전달합니다.
정보가 없으면 확정 요구와 임시 가정을 구분합니다. 알고리즘 이름을 찾은 것만으로 선택을 완료하지 않습니다.
간단한 기준안과 후보의 결과 품질, 최악 사례, 계산 비용을 같은 입력에서 비교합니다.
실행하지 않은 복잡도 추정과 측정 결과를 구분하고, 휴리스틱 결과를 최적해라고 주장하지 않습니다.

작은 입력에서는 독립 계산으로 기대값을 확인합니다. 실제 요구 규모에서는 누락, 중복, 제약 위반과 가장 불리한 대상의 결과를 확인합니다.
전체 대상이 처리되었거나 명시적인 예외로 설명되어야 합니다. 평균 개선만으로 일부 대상의 과도한 부담을 숨기지 않습니다.
업무상 소요 시간과 알고리즘 실행 시간을 구분합니다. 필수 상한이 미정이면 임의로 정하지 않고 영향과 남은 결정을 보고합니다.

## 데이터 변경과 보호

수용 조건의 작성자, 저장 위치와 접근 주체를 실제 코드 경계에 연결합니다.
UI에서 버튼을 숨기는 것과 서버에서 권한을 검사하는 것을 구분하고, 본인 데이터 접근 조건도 저장 또는 조회 경계에서 지킵니다.
로그인 상태만으로 타인 데이터 접근이 허용된다고 가정하지 않습니다.

입력 버전, 계산이 읽은 버전, 확정된 결과와 조회 대상이 어떻게 연결되는지 정합니다.
입력 변경 시 기존 계산을 취소할지, 완료 후 폐기할지, 별도 버전으로 보존할지는 프로젝트 정책을 따릅니다.
오래된 결과의 확정과 동시 확정을 막아야 한다면 저장 시점의 원자적 조건 검사로 보장합니다.
특정 DB나 큐를 강제하지 않으며 화면 잠금만으로 서버 동시성 보장을 주장하지 않습니다.

입력 유효성은 형식, 업무 의미와 데이터 간 관계 중 현재 요구에 필요한 경계를 확인합니다.
구현한 검사, 실제 검증한 검사, 미구현 조건과 입력에 대한 가정을 구분합니다.
잘못된 행을 제외하거나 보정하면 그 이유와 결과에 미친 영향을 확인할 수 있게 합니다. 조용히 누락시키지 않습니다.

## 중요한 선택의 기록

분석이나 구현 결과를 바꾸는 선택이 생기면 기존 작업 보고에 다음 정보를 짧게 연결합니다.

`분석 요청 / 비교한 결과 / 제안의 채택, 수정, 기각 / 결정 주체와 이유 / 검증 근거 / 남은 가정`

사람이 말하거나 승인한 선택만 사람의 결정으로 기록합니다. AI의 제안과 에이전트가 위임 범위에서 내린 선택은 구분합니다.
이미 있는 결정 기록이나 ADR은 링크하며 같은 내용을 다시 작성하지 않습니다.
매 도구 호출이나 사소한 변수명 선택을 기록하지 않습니다. 이해 확인 스킬의 호출 여부와 관계없이 중요한 선택의 근거를 보존합니다.
기록이 없으면 분석 지시나 판단 이유를 소급해서 만들어내지 않습니다.
