# 작업 계약

독립 작업을 위임하거나 순차 작업으로 나눌 때 필요한 항목만 채웁니다.

- 목표와 수용 조건 ID:
- 입력과 기존 인터페이스:
- 수정 가능한 파일:
- 만들어야 할 출력:
- 완료 조건과 검증 명령:
- 범위 밖 작업:
- 막히면 보고할 조건:
- 반환할 내용: 변경 위치, 실행 명령과 관측 결과, 남은 문제

작업자는 다른 작업자가 같은 저장소에서 작업 중일 수 있음을 전제로 기존 변경을 보존합니다. 계약 밖 파일이나 공용 기록을 변경해야 한다면 메인에게 먼저 알립니다. 메인은 수정 파일의 중복을 피하고 결과 통합과 기록 갱신을 담당합니다.

## 여러 쓰기 세션과 worktree

같은 저장소에서 여러 세션이 쓰기 작업을 하면 세션별 브랜치와 worktree를 우선 검토합니다.
읽기 전용 검토나 한 세션의 순차 작업에는 만들지 않습니다. 경로와 브랜치가 이미 있으면 소유자와 상태를 먼저 확인합니다.
worktree 사용만으로 여러 작업을 자동 생성하지 않습니다.

작업 계약에는 기준 브랜치와 SHA, 작업 브랜치와 경로, 수정 책임, 반환할 SHA와 검증 결과, 통합 담당자를 추가합니다.
각 작업자는 자신의 변경만 검증하고 커밋합니다. 공용 문서와 인터페이스의 편집 책임은 한 명으로 유지합니다.
worktree는 소스 작업 공간을 분리하며 DB, 포트, 실행 프로세스나 외부 서비스까지 자동 격리하지 않습니다.

통합 담당자는 기준 이후 변경과 의존 순서를 확인하고 기존 저장소 방식으로 완료 대상 브랜치에 통합합니다.
충돌은 양쪽 의도와 계약을 확인해 해결합니다. 사용자 변경을 임의로 버리거나 공유 이력을 다시 쓰지 않습니다.
통합 뒤 관련 검사를 다시 실행하고 완료 대상 HEAD, 반영한 작업 SHA와 남은 변경을 보고합니다.
작업 SHA의 반환과 최종 통합은 다른 상태입니다. 커밋이 보존되고 미커밋 변경이 없는지 확인하기 전에는 worktree를 정리하지 않습니다.
