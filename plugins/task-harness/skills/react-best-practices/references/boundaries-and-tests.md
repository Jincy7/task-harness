# 화면 경계와 테스트

## 폼과 비동기 상태

초기 로딩, 정상 결과, 빈 결과와 실패를 사용자에게 구분해 표시합니다. 저장 중 중복 제출 방지와 실패 후 재시도 경로를 정하고, 실패했다고 입력 초안을 지우지 않습니다. 낙관적 갱신을 사용하면 실패 시 복구와 새 요청과의 충돌을 처리합니다. 버튼 비활성화만으로 서버 멱등성이 보장된다고 판단하지 않습니다.

controlled input은 초기값과 변경 처리를 일관되게 유지합니다. 숫자 필드의 빈 입력을 곧바로 0으로 바꾸지 말고 편집 중 상태와 제출할 값을 구분합니다. 입력의 의미와 범위는 서버에서도 검증합니다.

## 사용자 조작과 서버 경계

- 클릭 가능한 `div` 대신 동작에 맞는 `button`과 링크를 사용합니다. 폼 제출 버튼과 일반 버튼의 `type`을 구분합니다.
- 입력에는 연결된 label을 두고 오류를 해당 입력과 연결합니다. 키보드 접근, 대화상자 진입과 닫기 후 초점, 비동기 결과 안내를 현재 흐름에서 확인합니다.
- 사용자 문자열은 기본 이스케이프를 유지합니다. 원시 HTML이 필요하면 신뢰 경계와 검증된 정화 방법을 명시합니다. 타입 단언으로 외부 응답 검증을 대신하지 않습니다.
- 서버 렌더링 환경이면 브라우저 API와 초기 렌더 결과를 확인합니다. Next.js 등 서버 컴포넌트가 있는 환경에서는 실제 버전의 서버와 클라이언트 경계를 지키고, 비밀값이나 서버 전용 모듈이 클라이언트 번들에 들어가지 않게 합니다. 일반 React 앱에 해당 프레임워크 규칙을 강제하지 않습니다.

## 검증할 관측

| 변경 경계 | 조작과 기대 결과 |
| --- | --- |
| 폼 | 입력, 제출, 실패, 재시도 후 초안과 결과 확인 |
| 조회 | 로딩, 빈 결과, 오류, 늦은 응답과 빠른 조건 변경 확인 |
| 목록 | 삽입, 삭제와 재정렬 후 항목별 상태 보존 |
| 접근성 | 키보드 이동과 실행, label과 오류 연결, 초점 복귀 |
| 서버 렌더링 | 새로고침과 전환 시 초기 표시, hydration 오류 확인 |

기존 테스트 도구에서 역할과 이름으로 요소를 찾고 사용자 조작 후 화면 결과를 확인합니다. 내부 state나 컴포넌트 이름에 묶인 테스트를 늘리지 않습니다. 네트워크 대역을 쓰면 응답 순서와 실패도 통제하고, 그 검사가 실제 서버 통합까지 증명한다고 보고하지 않습니다.
