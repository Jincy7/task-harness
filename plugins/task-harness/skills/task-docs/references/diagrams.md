# 다이어그램 작성과 표시

관계나 상태 전이는 그림으로, 입력과 출력 계약이나 실패 사례는 표로 설명합니다. 그림을 만들 이유가 없으면 생략합니다. 현재 구현과 예정 구조는 같은 그림에 섞지 않습니다.

## 형식 선택

표시 환경 확인은 약 2분을 목표로 합니다. 편집기의 Markdown 미리보기를 먼저 확인합니다. 버전이나 확장 이름만으로 Mermaid 렌더링 성공을 가정하지 않습니다.

| 확인한 환경 | 원본 | 읽는 형태 |
| --- | --- | --- |
| Mermaid 미리보기 동작 | Mermaid 코드 블록을 포함한 `.md` | Markdown 미리보기 |
| 미리보기 미지원, 허용된 로컬 렌더러 설치됨 | `.mmd` | 생성된 `.svg`를 문서에 표시 |
| 렌더러 부재 또는 실행 허용 미확인 | Markdown 표 또는 직접 작성한 SVG | 표 또는 로컬 이미지 |

그림마다 원본 형식을 하나 정하고 문서에 기록합니다. `.md`, `.mmd`, `.svg`를 각각 수동 원본으로 유지하지 않습니다. `.mmd`를 수정하면 파생 SVG도 다시 생성합니다. 재생성하지 못하면 그림을 표시하는 문서에 `갱신 필요`를 명시하거나 최신 내용의 표로 대체합니다.

기존에 설치되어 있고 사용이 허용된 `mmdc`의 명령을 확인한 경우에만 다음 형태를 사용합니다.

```sh
mmdc -i docs/diagrams/request-flow.mmd -o docs/diagrams/request-flow.svg
```

이것은 명령 형식 예시이며 실행 성공 기록이 아닙니다. 렌더러나 브라우저의 설치와 다운로드를 기본 단계에 넣지 않습니다. 원격 렌더 서비스, 외부 폰트, 아이콘, 스크립트를 사용하지 않습니다.

## 직접 작성한 SVG

[합성 흐름 예시](../assets/flow-example.svg)는 SVG 자체가 원본입니다. 대상 프로젝트의 구현을 나타내지 않습니다. 설명에 도움이 될 때만 실제 내용으로 바꾸어 사용합니다.

생성하거나 수정한 그림은 가능한 로컬 뷰어에서 열어 글자, 연결선, 잘림을 확인합니다. XML 문법 검사와 실제 표시 확인은 구분합니다. 표시를 확인하지 못하면 미확인으로 기록하고 텍스트 설명을 함께 제공합니다.
