# 문서 템플릿

필요한 문서 부분만 사용합니다. 기존 파일을 덮어쓰지 않으며, 빈 항목은 채울 근거가 없으면 생략하거나 미확인으로 표시합니다. 경로와 링크는 대상 저장소의 실제 구조에 맞춰 작성합니다.

## 문서 지도

```markdown
# 문서 지도

현재 작업:

| 문서 | 경로 | 기록하는 정보 |
| --- | --- | --- |
| | | |

체크리스트 원본:
작업 보고 위치:
```

지도는 실제 작성된 문서로 연결합니다. 예정 문서는 예정이라고 표시하며 존재하지 않는 파일로 링크하지 않습니다.

## 스펙

```markdown
# 작업 주제

## 목표와 범위

- 현재 흐름:
- 다음 흐름:
- 제외:

## 기대 동작과 수용 조건

| ID | 사용자 행동 | 입력과 상태 변화 | 성공 결과 | 실패 처리 |
| --- | --- | --- | --- | --- |
| | | | | |

## 미결사항과 가정

| 항목 | 바뀌는 구현 결정 | 지금 질문 / 가정 / 보류 | 근거와 재확인 시점 |
| --- | --- | --- | --- |
| | | | |

## 관련 결정

```

## 플랜

플랜은 체크리스트입니다. 항목에는 작업 ID, 할 일과 수용 조건 ID, 필요하면 짧은 담당 또는 막힘 표시만 둡니다. 완료한 항목은 해당 작업 보고에 연결합니다.

```markdown
# 구현 체크리스트

스펙: 실제 스펙 링크

- [ ] T1 실행 기록 경로 준비와 안전한 실패 수집 확인
- [ ] T2 첫 사용자 흐름 구현 (AC-1)
- [ ] T3 저장 실패와 재시도 확인 (AC-2)
- [ ] T4 직접 조작이 필요한 화면 확인 (AC-3)
```

위 항목은 앱 구현의 예시이며 현재 작업에 맞게 바꿉니다. 문서 수정이나 기록 경계에 영향이 없는 변경에 로거 준비를 반복하지 않습니다. 체크 완료 시 항목 끝에 실제 보고서 링크를 붙입니다. 작업 계약, 실행 이력, 검증 표와 회고는 플랜에 추가하지 않습니다.

## 작업 보고

`docs/reports/<topic>/<work-id>.md`를 기본으로 사용하고 기존 보고 경로가 있으면 유지합니다. 작업 단위로 파일을 나누며 같은 작업의 수정 전후 실행은 한 보고서에 연결합니다. 매 명령마다 보고서를 만들거나 다른 작업을 계속 덧붙이지 않습니다.

```markdown
# 작업 결과

관련 스펙과 플랜:
작업 ID와 변경 범위:
확인 시점과 대상 코드 상태:

## 변경과 검증

| 수용 조건 | 구현 위치 | 실행 ID와 명령 또는 조작 | 기대와 실제 결과 | 통과 / 실패 / 미확인 | 근거 위치 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

로그 및 출력 수집 상태: complete / partial / unavailable

## 이상 상황과 해결

- 사건과 상태:
- 현상, 재현 조건과 근거:
- 예상한 실패 여부와 판단 근거:
- 원인 가설 / 확인된 원인:
- 제안한 해결 방안 / 실제 적용한 조치:
- 수정 후 재검증과 영향받는 회귀 확인:
- 미해결 사항과 다음 확인:

## 남은 확인

| 조작 또는 검사 | 기대 결과 | 미확인 이유 | 다음 행동 |
| --- | --- | --- | --- |
| | | | |
```

원본 출력은 실행별 `.local/` 경로에 두고 보고서에는 재현에 필요한 요약과 위치만 기록합니다. 공유할 보고서가 로컬 근거를 가리키면 별도 보관 자료임을 밝히고, 필요한 근거를 정제해서 함께 전달합니다. 근거가 없는 항목을 통과나 원인 확인으로 채우지 않습니다. 사용자 조작에서 의도한 거절과 오류를 유도한 테스트는 예상 밖 실패와 구분합니다.

기존 장부가 있으면 과거 기록을 보존하고 연결합니다. 사용자가 기존 플랜 분리를 요청한 경우에만 과거 이력을 시점과 함께 보고서로 옮깁니다. 구현 작업의 체크 완료에는 수용 조건의 실행 근거가 필요하며 문서 완료와 제품 완료를 구분합니다.

## ADR

```markdown
# ADR-0001: 결정 제목

상태: 제안 / 채택 / 대체됨
관련 스펙:
대체 관계:

## 결정

## 근거와 고려한 대안

## 구현

## 검증과 한계

```

번호와 상태는 실제 기록에 맞춰 선택합니다. 결정이 바뀌면 이전 문서와 새 문서에 서로의 위치를 기록합니다.
