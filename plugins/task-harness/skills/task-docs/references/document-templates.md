# 문서 템플릿

필요한 문서 부분만 사용합니다. 기존 파일을 덮어쓰지 않으며, 빈 항목은 채울 근거가 없으면 생략하거나 미확인으로 표시합니다. 경로와 링크는 대상 저장소의 실제 구조에 맞춰 작성합니다.

## 문서 지도

```markdown
# 문서 지도

현재 작업:

| 문서 | 경로 | 기록하는 정보 |
| --- | --- | --- |
| | | |

작업 상태와 검증 근거의 원본:
```

지도는 실제 작성된 문서로 연결합니다. 예정 문서는 예정이라고 표시하며 존재하지 않는 파일로 링크하지 않습니다.

## 스펙

```markdown
# 작업 주제

## 목표와 범위

- 현재 흐름:
- 다음 흐름:
- 제외:

## 기대 동작과 수용 조건

| ID | 사용자 행동 | 입력과 상태 변화 | 성공 결과 | 실패 처리 |
| --- | --- | --- | --- | --- |
| | | | | |

## 미결사항과 가정

| 항목 | 바뀌는 구현 결정 | 지금 질문 / 가정 / 보류 | 근거와 재확인 시점 |
| --- | --- | --- | --- |
| | | | |

## 관련 결정

```

## 플랜

```markdown
# 구현 계획

스펙 위치:
작업 장부 위치:

## 현재 흐름

| 작업 | 요구 ID | 담당 | 수정 범위 | 입력과 출력 | 주요 경계 | 검증 명령 | 상태 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |

## 검증 근거

| 요구 ID | 구현 위치 | 명령과 작업 위치 | 입력과 기대 결과 | 실제 관측과 시점 | 통과 / 실패 / 미확인 | 한계 |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | | |

## 직접 확인

| 조작 | 기대 결과 | 사람이 확인해야 하는 이유 | 결과 |
| --- | --- | --- | --- |
| | | | |

## 다음 작업과 막힌 조건

```

기존 장부가 원본이면 위 작업표와 검증표를 복제하지 않고 링크로 대체합니다. 구현 작업 완료에는 수용 조건의 실행 근거가 필요합니다. 문서 작업 완료와 제품 완료를 구분합니다.

## ADR

```markdown
# ADR-0001: 결정 제목

상태: 제안 / 채택 / 대체됨
관련 스펙:
대체 관계:

## 결정

## 근거와 고려한 대안

## 구현

## 검증과 한계

```

번호와 상태는 실제 기록에 맞춰 선택합니다. 결정이 바뀌면 이전 문서와 새 문서에 서로의 위치를 기록합니다.
