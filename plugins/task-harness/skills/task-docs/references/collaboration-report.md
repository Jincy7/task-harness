# AI 협업 기록과 요구된 산출물

협업 설명이나 지정 제출 문서가 요구된 경우에 읽습니다. 기존 작업 보고와 결정 기록에서 근거를 가져옵니다.
문서 작성만을 위해 수행하지 않은 분석, 사용자의 승인이나 검증을 만들어내지 않습니다.

## 협업 설명

요구된 질문과 문서명을 그대로 유지합니다. `AI_COLLABORATE` 형식이 아래 세 항목이면 다음 근거를 연결합니다.

| 질문 | 기록에서 가져올 근거 |
| --- | --- |
| 까다로운 예외나 장애, 어떻게 수정했는가 | 재현 입력, 실패 현상, 수정과 재검증 결과, 미해결 범위 |
| AI를 다루는 엔지니어가 가장 중요하게 검증할 것은 무엇이며 어떻게 검증했는가 | 이번 작업에서 결과를 좌우한 위험, 선택 이유, 독립적인 기대값과 실제 관측 |
| AI 제안에서 무엇을 바꾸고 받아들였는가 | 실제 제안, 채택 또는 수정 및 기각, 결정 주체와 이유, 결과에 미친 영향 |

일반론으로 항목을 채우지 않습니다. 주장을 작업 ID, 결정 기록이나 검증 사례로 추적할 수 있게 합니다.
사용자가 결정한 정책과 에이전트가 위임 범위에서 정한 구현을 구분합니다.
기록이 없는 이유는 미확인으로 남기며 회고에서 추정한 이유는 당시 판단과 구분합니다.
형식에서 본문을 요구하면 근거의 요지를 함께 쓰고 링크만 나열하지 않습니다. 기록 전체나 대화 원문을 복제하지 않습니다.

## 산출물 확인

요구 문서에서 지정한 파일명과 각 완료 조건을 먼저 추출합니다.
`HOW_TO_RUN`, `Dockerfile`, 협업 문서가 요구됐을 때만 해당 산출물을 준비합니다. 모든 저장소의 기본 파일로 만들지 않습니다.
실행 안내에는 실제 확인한 명령, 전제와 성공 확인 방법을 쓰고 실행하지 못한 단계는 구분합니다.
파일 존재, 문법 검사, 실제 빌드 및 실행 성공은 다른 근거입니다. 파일이 있다는 이유로 빌드 가능하다고 쓰지 않습니다.
README와 별도 실행 안내가 함께 필요하면 각 문서의 역할과 링크를 정해 명령 원본이 서로 어긋나지 않게 합니다.
