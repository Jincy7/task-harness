# Task Harness 0.8.1 변경과 검증

확인일: 2026-10-31
대상: task-harness 지침 패키지, 기존 `0.8.0` 이후 변경

## 변경 범위

- 업무 관찰과 정책 결정의 분리, 후보별 영향과 예외 확인
- 분석 목적과 필수 제약, 최악 결과와 전체 대상 검증
- 데이터 소유권, 입력 버전, 확정과 동시 요청의 계약
- 실제 AI 분석 요청과 제안의 채택, 수정, 기각 기록 및 지정 산출물 연결
- 허용된 브라우저 자동 검증, 패키지 재사용과 여러 쓰기 세션의 worktree 통합 지침
- 저장소의 실제 작업 근거에서 기본 여섯 문항 생성, 무관한 영역 대체와 근거 부족 시 축소
- 사용자 보고를 보존하는 동일 환경 전용 선택 참조

실행환경 코드는 변경하지 않았습니다. 복기의 환경 설정이나 도구 권한을 현재 관측으로 승격하지 않습니다.
일반 패키지 내용 검사에서는 승인된 복기 참조 파일 한 개만 맥락별 용어를 허용합니다. 나머지 파일과 스킬 진입점에는 기존 일반성 검사를 유지합니다.

| 검사 | 실행 | 결과와 한계 |
| --- | --- | --- |

| 스킬 형식 | `uv run --with pyyaml python /Users/changyeobjin/.codex/skills/.system/skill-creator/scripts/quick_validate.py <skill-directory>` | 여덟 스킬 모두 통과, 판단 품질의 증명은 아님 |
| 변경 형식 | `git diff --check` | 통과 |

## 일반 수정 요청의 커밋 확인

저장소 밖의 임시 Git 저장소에 생성 템플릿의 완료 조건을 배치한 뒤 기준 커밋을 만들었습니다.
별도 에이전트에 “README 사용 안내 링크가 열리지 않으니 실제 파일에 맞게 수정하고 로컬 링크를 검증”하도록 요청했습니다.
요청에는 스킬명이나 커밋 지시를 넣지 않았습니다. 에이전트는 저장소의 `AGENTS.md`를 읽도록 안내받았습니다.

- 기준 SHA: `dcc0037c2055d3dc218ae1fc3b924b0e1bb812cd`
- 작업 SHA: `aca156ade25575e352e5e275992904153e6162c3`
- 직접 대조: README 한 줄 수정, 실제 안내 파일 연결, 작업 커밋 생성, 깨끗한 작업 트리
- 범위: 합성 문서 수정 한 건, 실제 제품 구현과 설치된 플러그인의 자동 로딩은 별도 미확인

원본 작업공간과 기준 SHA 위치는 `.local/runs/0.8.1/commit-fixture.txt`에 보존했습니다.
해당 파일은 Git에서 제외한 로컬 자료이며 다른 체크아웃에 포함되지 않습니다.

## worktree 통합 확인

별도 임시 저장소에서 작업 worktree와 브랜치를 만들고 작업 커밋을 생성했습니다.
완료 대상 브랜치에서 `git merge-base --is-ancestor <worker-sha> HEAD`가 통합 전에는 종료 코드 1을 반환했습니다.
`git merge --ff-only` 뒤에는 종료 코드 0을 반환했고 실제 파일 내용과 깨끗한 작업 트리를 대조했습니다.

작업 SHA는 `9318d99579dcce8752604923583bd20e68090ba5`입니다.
이는 커밋 반환과 통합 상태를 구분하는 합성 Git 확인이며 충돌 해결, DB 또는 프로세스 격리를 검증한 결과가 아닙니다.
원본 결과는 Git에서 제외한 `.local/runs/0.8.1/worktree-check.json`에 있습니다.

## 독립 합성 사용 검증

별도 에이전트에 다섯 요청과 합성 입력을 주고 해당 스킬을 수행하도록 했습니다.
제안한 수정의 정답이나 기대 판정은 전달하지 않았으며 반환 문항과 근거를 직접 검토했습니다.

| 요청 | 실제 반환에서 확인한 내용 |
| --- | --- |
| CSV 변환 CLI의 최종 질문 6개 | 불량 행, BOM, ID 선행 0, 중복 ID, 덮어쓰기와 실패 시 파일 보존에 대한 질문, 로그인이나 서버 및 알고리즘 분석을 전제하지 않음 |
| 예약 API의 최종 질문 6개 | 실제 권한과 서버 동시성 판단, 미검증 변경 경합 및 미정 보존 정책을 구분한 질문 |
| 대기시간 관찰로 범위 정리 | 10분과 15분을 비교 후보로만 사용, 고정 분포의 수계산과 실제 알고리즘 실행 구분, 정책 미정 유지 |
| 100명 배정 결과 검토 | 평균 22.2분과 최대 240분 구분, 실행 0.2초를 업무 품질로 확대하지 않음, 상한 미정으로 적합성 미확인 |
| 제한된 기록으로 협업 문서 작성 | 알려진 정책 선택과 검사 결과만 사용, 당시 이유와 분석 지시 및 디스크 오류 검사 미확인 유지 |

원본 응답은 Git에서 제외한 `.local/runs/0.8.1/forward-check.md`에 보존했습니다.
위 결과는 합성 입력에 대한 지침 적용 확인입니다. 실제 제품을 실행하거나 사용자 이해를 측정한 결과가 아닙니다.

## 미확인 범위

실제 앱의 브라우저, 인증과 동시성 실행, Docker 빌드, 실제 사용자의 문답 효과는 이번 검증에서 수행하지 않았습니다.
새 버전의 플러그인 설치 또는 캐시 갱신과 원격 push는 수행하지 않았습니다.
